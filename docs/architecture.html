    docker compose

    Local development stack

    Run make up. Four services start in one Docker network. Nginx is the only container with a published port (8080). PHP source code is bind-mounted for instant hot-reload without rebuilding the image.

    ⚡ Hot-reload
    The ./app/src directory is mounted into the PHP-FPM container as a bind mount. Every file save is immediately live — no rebuild, no restart. The docker-compose.override.yml adds Xdebug config on top.
    🌐 Network isolation
    The backend network is internal: true, blocking internet access from PHP and MySQL. Only Nginx bridges to the frontend network where port 8080 is published. Adminer also bridges both networks for DB access.
    kubernetes

    Pod anatomy — sidecar pattern

    In Kubernetes, Nginx and PHP-FPM share a single Pod. An initContainer bridges the gap: it copies PHP files into a shared emptyDir volume, giving both containers access to the application without duplicating the image.

    💡 Why sidecar?
    Nginx needs static files to serve directly and PHP files to hand to FastCGI. Rather than baking Nginx config with the app image (coupling), they are separate containers that share one volume. They scale together as a unit and communicate over localhost — no network hop.
    🔒 Security posture
    PHP-FPM runs as www-data (uid 82). readOnlyRootFilesystem: true on the PHP container — emptyDir volumes provide the writable paths (/tmp and /var/www/html from the init). DB password comes from a Kubernetes Secret, never the image or ConfigMap.
    helm chart

    Chart structure

    A single chart renders all resources for any environment. The values files cascade: values.yaml sets defaults; environment files override only what changes.

    ├── service-mysql.yaml  ClusterIP + headless
    ├── ingress.yaml        nginx-ingress class
    └── hpa.yaml            CPU+mem, v2 API
    deployment-app.yaml
    The heart of the chart. Defines a RollingUpdate Deployment with the initContainer + nginx + php-fpm sidecar pattern. maxSurge: 1, maxUnavailable: 0 ensures zero-downtime deploys. References the nginx ConfigMap and app Secret by name.
    statefulset-mysql.yaml
    MySQL as a StatefulSet with a volumeClaimTemplate for the PVC. A sibling ConfigMap holds the init.sql script mounted at /docker-entrypoint-initdb.d/. A headless Service enables stable DNS (linexa-mysql-headless) for the StatefulSet.
    hpa.yaml (production only)
    HorizontalPodAutoscaler using the autoscaling/v2 API. Scales on both CPU (65%) and memory (75%). Scale-down is stabilized for 5 minutes to avoid thrashing. Scale-up adds at most 2 pods per minute.
    secret-app.yaml — ⚠ replace
    Ships with changeme placeholders and helm.sh/resource-policy: keep (survives helm uninstall). Replace with Sealed Secrets, External Secrets Operator, or SOPS before any shared deploy.

    📝 Code PR → Helm Lint
    Every PR touching helm/** triggers helm-lint.yml: lints all three value sets, renders staging + production templates with helm template, and validates with kubeval. No broken manifests can merge.
    🔀 Merge → Build (auto)
    build-push.yml runs on merge to main. Builds the multi-stage PHP image, pushes to GHCR with the short SHA tag, then commits tag: "sha-abc1234" back into values-staging.yaml — triggering ArgoCD without any manual step.
    ☸ Staging Sync (auto)
    ArgoCD polls the git repo every 3 minutes. When it detects the tag bump, it runs helm upgrade against the staging namespace. Self-heal is on: any manual kubectl change is reverted back to what git says within minutes.
    🎯 Promote → Prod (manual PR)
    To promote, update values-production.yaml with the verified SHA, open a PR, get a review, and merge. ArgoCD notices the change but does NOT auto-sync production — a deliberate manual argocd app sync linexa-production or UI click is required.
